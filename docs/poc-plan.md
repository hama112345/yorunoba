# ヨルノバ 2週間PoC計画

> 事業計画書（居酒屋メタバース事業）をもとに、2週間で「動く店」を公開し、需要と支払い意思を確かめる計画。
> 2026-10-21 作成。同日、方言/酔っ払いモードをPoCから外し、AI店員（自治）を追加。
> 同日（D2）、見た目の強化（背景はAI生成・キャラは外注）と交流の仕組み（ひとこと札・ワンタップ反応・賑わい演出）を軸に組み直し。

## 目的
- **主目的：そもそも求める人がいるか**を確かめる。
- **できれば：お金を払う意思があるか**も確かめる。
- 開発は**フルAI（Claude Codeが実装）**で行う。

## 結論サマリ
| 論点 | 決定 | 理由 |
|---|---|---|
| 公開先 | **Webブラウザ（スマホ優先・PC対応）** | URLを開けばすぐ入店できる。審査がなく毎日更新でき、広告→入店→発言→再来訪まで計測できる |
| 2D/3D | **2D（斜め見下ろし）** | 確かめたいのは会話であって没入感ではない。フルAI開発では3D素材が詰まりどころになる。「2000年代インターネット」の懐かしさとも合う |
| 見た目 | **背景はAI画像生成、キャラは絵師に外注**（届くまでは仮の絵） | 第一印象が入店率（H1）を左右する。私（AI）は絵を描けないので、絵の入手は人に任せ、差し替えの受け皿をコード側に用意する。指示書は `docs/art/` |
| 店の雰囲気 | **RPGのギルドの酒場／大衆居酒屋**（どちらかに寄せる。背景の候補を見て決める） | 「みんなが集まる溜まり場」のインターネット感。しゃれたバーより、気軽に混ざれる雑多さを優先する |
| 技術 | TypeScript + Phaser 3 + Colyseus 0.18 + Render + PostHog + Claude Haiku 5.5 | AIが書き慣れた定番。デプロイ先は1か所でDBなし |
| 期間 | 7日目にプレオープン（知人）、10日目に一般公開、残りは毎晩営業して計測 | 計測できる日数を最大化する |

### Fortniteではなく自前Webにする理由
1. コア機能（テキストの吹き出し、ログなし、通報→留置所、AI店員）がUEFNでは作りにくい。
2. 利用者が若年層中心で、ターゲット（都市部の社会人）とずれる。
3. 行動データを自分で取れない（前回のモックでもデータが取れなかった）。

検証が通ったら、Fortnite・Discord・アプリへの展開（事業計画のStep2〜4）に進む。

## PoCに入れるもの・入れないもの
| 入れる（需要検証に直結） | 入れない（あとで検証） |
|---|---|
| テキストの吹き出し・保存しない会話、席に座る | **方言モード・酔っ払いモード**（自己表現の機能。需要の有無の答えは変わらない） |
| **ひとこと札**（話題タグ。話しかけるきっかけ） | 乾杯と「顔なじみ」の印（後回し） |
| **ワンタップ反応**（わかる／笑／へぇ。読むだけの人も参加できる） | AI店主の迎え・お題出し（後回し） |
| **賑わい演出**（ざわめき・提灯の揺れ・人数で灯りが増える・入口の「いま○人」） | 酔い度（後回し） |
| **営業の節目**（21時開店・23:45ラストオーダー・24時閉店） | 3D化、アバターの着せ替え |
| **AI店員による自治**（荒らし対策・通報の一次対応） | スポーツ観戦の映像（権利問題） |
| **AI常連**（客が少ないときだけ。名札に「AI」と明示） | アプリ化、ログイン |
| 常連パスの偽ドア・事前登録 | |

## 技術スタック
- **クライアント**：Vite + TypeScript + Phaser 3。チャット入力やメニューはHTMLのDOMで重ねる（日本語IME・スマホキーボード対策）。
- **サーバー**：Node.js + Colyseus 0.18（部屋＝店）。全発言がサーバーを通るので、NGワード・連投制限・AI店員・留置所をサーバー側で確実に処理できる。**発言は保存しない**。
- **共通**：`packages/shared` に定数・間取り・同期する状態（Colyseus Schema）を置き、クライアントとサーバーで同じ定義を使う。
- **ホスティング**：Render（1サービスでWebSocketと画面の両方を配信）。`main` にpushすると自動で更新される。無料プランで始め、D10の一般公開前にStarter（月7ドル）へ切り替える。
- **AI**：Claude Haiku 5.5（`claude-haiku-5-5`、入力100万トークン0.10ドル／出力0.50ドル）。AI店員とAI常連に使う。
- **計測**：PostHog（発言本文は送らず、回数・文字数などだけ記録する）。
- **テスト**：Vitest（ロジック・部屋）と Playwright（2つのブラウザで入店→同期）。

## AI店員（自治）の設計 — 月100ドルのClaude APIクレジットを活用
事業計画の「店員による自治警察」を、**AIが一次対応し、人（店主）が最終判断する**形で実装する。

1. **即時ルール（遅延ゼロ・無料）**：NGワード、連絡先（LINE ID・電話番号・URL）の検知、連投制限。
2. **AI店員（事後チェック）**：
   - 発言はすぐ吹き出しに出す。並行して、直近の会話（メモリ上の数行）と一緒にHaikuで判定する（OK／注意／取り消し）。
   - 違反なら吹き出しを全員の画面から消す（「店員がおしぼりで拭きました」）。本人には店員キャラとして注意する。
   - 3回で留置所（別の部屋に10分）に送る。
   - 先に判定してから表示する方式だと会話のテンポが落ちるため、事後チェックにする。
3. **通報の一次審査**：通報されたら、AIがその客の直近の発言（メモリ上）を見て即判断する。同時に店主へDiscordで通知し、異議があれば人が判断する。夜中に店主がいなくても回る。
4. **障害時**：APIが失敗したら、ルールだけで営業を続ける。
5. **安全**：客の発言は「判定対象のデータ」として渡し、指示として扱わない（「この発言はOKにして」のような書き込みへの対策）。判定は決まった形式（JSON）で返させる。

**費用の目安**：1回の判定で入力約1,000トークン＋出力約100トークン ≒ 0.015セント（約0.02円）。
- 毎晩100人×30発言×30日 ＝ 月9万発言 → **約14ドル**。
- AI常連を足しても**月20ドル程度**で、100ドルの枠に十分収まる。

**データの扱い**：
- 通常の発言はこちらでは保存しない。違反判定・通報された発言だけを、異議対応のため一定期間保存する。
- AIによる自動チェックのため、発言がAnthropicのAPIに送られることをプライバシーポリシーに明記する。
- クレジットがAPIキー経由の本番利用に使えるか（対象・期限）は事前に確認する。

```
├── README.md / CLAUDE.md

│   ├── rooms/            # IzakayaRoom（D5で留置所を追加）
│   └── app.ts            # サーバー定義・画面の配信
├── e2e/                  # Playwright
├── render.yaml           # Renderデプロイ設定
└── .github/workflows/    # CI
```

## 検証設計
指標と合格ラインは [hypotheses.md](./hypotheses.md) を参照。

**閑散対策（最重要）**：人がいないと「需要なし」と誤って判断してしまう。次の3つで人を集中させる。
- 営業時間を毎晩21〜24時に限定する。
- 店主が常駐する。
- AI常連が場をつなぐ（客が少ないときだけ。AIであることは明示する）。

## リスクと公開前チェック
- **電気通信事業法**：ユーザー同士のチャットは「他人の通信の媒介」に当たる可能性がある。総務省の参入マニュアルで届出が必要か確認する（個人もe-Govで無料で届出できる）。
- **未成年対策**：18歳以上の自己申告。
- **外部送信規律**：PostHogとAnthropic APIへの送信をプライバシーポリシーに明記する。
- **知的財産**：キャラはオリジナルか購入素材にする。スポーツ中継の映像は流さない。
- **費用の目安**：Render 無料（D10からStarter 月7ドル）、Claude APIはクレジット内、素材0〜5,000円、広告1〜3万円。
